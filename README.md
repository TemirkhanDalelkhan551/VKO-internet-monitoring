# VKO Internet Monitoring

Рабочий прототип системы автономного мониторинга интернет-соединения для школ ВКО.

## Зафиксированное состояние — 24.09.2026

Публичная панель: https://vko-internet-monitoring-api.onrender.com/ . Приложение вручную опубликовано на Render из коммита `0c4ff6e` и имеет статус `Live`; readiness API и PostgreSQL подтверждены как `Healthy`. В GitHub `main` добавлено последующее обновление документации. Автодеплой отключён. Для подключения другого компьютера нужен один файл `VkoInternetMonitoringAgent-Setup-1.5.0-win-x64.exe`. Школу и линию создаёт администратор в панели; там же выдаётся одноразовый код. На другом ПК установщик запускается с правами администратора: рабочий адрес API уже заполнен, мастер сначала без расходования кода проверяет сервер и показывает школу/линию, затем активирует компьютер после подтверждения. .NET Runtime отдельно не требуется. Совместимый API опубликован на Render. Установка и активация версии 1.1.0 на втором физическом компьютере подтверждены 19.09.2026. Инструкция: [WEB_ACTIVATION.md](docs/WEB_ACTIVATION.md).

Полевое обновление до 1.2.0 выявило, что ранее запущенная служба могла остаться остановленной после замены файлов. В 1.2.1 установщик восстанавливает исходное состояние `Running`, а кнопка ручного замера дополнительно запускает остановленную службу. Версия 1.3.0 получает расписание из веб-панели. Версия 1.4.0 восстанавливает частично завершённую активацию на том же компьютере в течение 24 часов и добавляет управляемый жизненный цикл устройств. Версия 1.5.0 добавляет обращение из программы с фактическими замерами, пояснение статуса и мини-график. Обновление выполняется поверх текущей версии без нового кода активации.

## Что уже работает

- фоновый агент на .NET 10;
- пользовательский API входа/выхода, блокировки, смены пароля и отзыва сессий;
- пять ролей ТЗ с разграничением школ, районов и линий провайдеров на сервере;
- журнал аудита административных действий и авторизации;
- расписание из 3–5 измерений в сутки со стабильным случайным смещением;
- независимые измерения Download, Upload, Ping, Jitter и Packet Loss;
- фиксация длительности теста, фактического Ethernet/Wi-Fi и выбранного сервера измерения;
- определение внешнего IP сервером без доверия к значению от агента;
- откладывание замера при высокой загрузке CPU или фоновой сетевой активности;
- корректные статусы `Online`, `Degraded`, `Offline` и причины неполного измерения;
- локальная очередь, карантин повреждённых файлов и ограничение её размера;
- повторная отправка с экспоненциальной задержкой и jitter;
- API приёма измерений с токеном устройства;
- независимый heartbeat агента с фиксацией последней связи и версии;
- серверная защита от дубликатов по `EventId`;
- регистрация устройств с одноразовой выдачей токена и хранением только его SHA-256-хэша;
- графический мастер первичной активации: ввод адреса сервера, одноразового кода, названия компьютера, кабинета и типа подключения;
- локальная панель состояния только этого компьютера: служба, последняя связь, текущий статус, метрики и 20 последних измерений;
- ручной тестовый замер из локальной панели без ожидания ближайшего окна расписания;
- безопасное сохранение выданного токена через Windows DPAPI и автоматический запуск службы после активации;
- API школ, устройств, истории измерений и агрегированной аналитики;
- вычисление статусов `Normal`, `Unstable`, `Critical` и `NoConnection` по порогам ТЗ;
- локальные Download/Upload endpoints;
- последние измерения, доступные по персональной Bearer-сессии и области роли; общий админ-токен на Render отключён;
- карта школ с проверяемыми координатами, общими фильтрами и переходом в карточку;
- создание/редактирование школ, контактов, линий и реквизитов договоров;
- выдача одноразового кода активации через веб-панель, реестр статусов и отзыв неиспользованного кода;
- CSV/XLSX с фильтрами и аналитика выбранного календарного периода;
- список и карточка инцидентов, комментарии, ответственный, разрешённые переходы статуса и история;
- администрирование пользователей, ролей, областей доступа, аудита и устройств;
- удалённые окна замеров и пороги качества, которые агент получает при служебной связи;
- сводки районов/поставщиков, центр уведомлений и обращение провайдеру с ручной проверкой и печатью/PDF.

AI-черновик обращения использует только данные инцидента и агрегированные фактические замеры; он остаётся редактируемым и никогда не отправляется провайдеру автоматически. Для включения задайте в секретах среды `OpenAiAppealDraft__Enabled=true`, `OpenAiAppealDraft__ApiKey` и `OpenAiAppealDraft__Model`. Ключ не добавляйте в Git.

Telegram-оповещения об автоматическом открытии и восстановлении инцидентов реализованы как необязательная фоновая доставка и выключены до настройки секретов Render. Инструкция и границы первой версии: [TELEGRAM_NOTIFICATIONS.md](docs/TELEGRAM_NOTIFICATIONS.md).

API поддерживает PostgreSQL через `PostgresMeasurementRepository`. JSON остаётся режимом по умолчанию для быстрой локальной разработки и тестов без внешней базы.

## Требования для разработки

- .NET SDK 10.0.401 или совместимая более новая версия;
- Windows 10/11 x64;
- PowerShell 5.1 или новее для установочных скриптов.

.NET 10 не поддерживает Windows 7 и Windows 8.1. Перед массовой установкой необходимо собрать инвентаризацию версий Windows в школах.

## Сборка и тесты

```powershell
dotnet restore .\VkoInternetMonitoring.sln
dotnet test .\VkoInternetMonitoring.sln --configuration Release
dotnet build .\VkoInternetMonitoring.sln --configuration Release
```

На компьютере с ошибкой CET сначала завершите все обновления Windows и перезагрузите систему. Временный локальный обход через Roslyn из Visual Studio предназначен только для разработки и не является требованием агента.

## Локальная end-to-end проверка

В первом PowerShell запустите API:

```powershell
dotnet run --project .\src\VkoMonitoring.Api --launch-profile http
```

Во втором PowerShell запустите агент:

```powershell
dotnet run --project .\src\VkoMonitoring.Agent -- `
  --RunAsConsole=true `
  --environment Development `
  --Agent:RunImmediatelyOnStartup=true
```

После успешной отправки локальная очередь агента очистится, а событие появится в `data\measurements` относительно каталога запущенного API.

Получить последнее измерение:

```powershell
Invoke-RestMethod `
  -Uri "http://localhost:5080/api/measurements/recent?limit=1" `
  -Headers @{ "X-Admin-Token" = "local-development-admin-token" }
```

## Проверка через реальный интернет

Сначала запустите локальный API командой из предыдущего раздела. Затем во втором
PowerShell запустите агент с отдельным профилем реального измерения:

```powershell
dotnet run --project .\src\VkoMonitoring.Agent -- `
  --RunAsConsole=true `
  --environment RealMeasurement
```

В этом режиме Ping выполняется до `1.1.1.1`, а Download и Upload — через
`speed.cloudflare.com`. Локальный API только принимает готовый результат.
Использование внешнего измерительного узла подходит для полевой проверки, но для
промышленной системы необходимо развернуть собственные контролируемые endpoints.

Если результат содержит `MeasurementServerUnavailable` и ошибку TLS, сначала
завершите обновления Windows и перезагрузите компьютер: агент не подменяет
недоступные метрики вымышленными значениями, а отправляет диагностический статус
`Degraded`.

## Конфигурация

При графической активации идентификаторы и токен выдаёт сервер автоматически. Приведённые ниже поля относятся к ручной настройке профилей разработки; не копируйте токен с одного школьного компьютера на другой. Для ручного профиля замените демонстрационные значения:

- `SchoolId`;
- `DeviceId`;
- `LineId`;
- `DeviceToken`;
- `ApiBaseUrl`;
- адреса Download/Upload тестов;
- PingHost;
- 3–5 окон измерений.

Не сохраняйте настоящие токены в Git. Установочный скрипт переносит токен в файл, защищённый Windows DPAPI для текущего компьютера, удаляет открытое значение из `appsettings.json` и ограничивает доступ к файлу учётными записями `SYSTEM` и локальных администраторов. Открытый `DeviceToken` допускается валидатором только для loopback-разработки.

Установленная служба записывает диагностический журнал в `C:\ProgramData\VkoInternetMonitoringAgent\logs`. По умолчанию один файл ограничен 5 МБ, журналы хранятся 14 дней. Параметры `DiagnosticLogMaxFileSizeBytes` и `DiagnosticLogRetentionDays` можно изменить в секции `Agent`; токены в журнал не записываются.

Чтобы тест скорости не мешал пользователю, агент перед запуском замера проверяет
общую загрузку компьютера и сети. По умолчанию замер разрешён при CPU не выше
70% и фоновой сетевой активности не выше 5 Mbps. Пороговые значения задаются
параметрами `MaximumCpuUsagePercent`, `MaximumBackgroundNetworkMbps`,
`SystemLoadSampleMilliseconds`, `SystemLoadRetrySeconds` и
`MaximumLoadDeferralSeconds`.

## Публикация и обновление агента

```powershell
.\scripts\publish-agent.ps1
```

Первая установка выполняется из PowerShell с правами администратора:

```powershell
.\scripts\install-agent.ps1
```

Пакет `artifacts\agent-win-x64` содержит два основных файла:

- `VkoMonitoring.Agent.exe` — фоновая Windows-служба;
- `VkoMonitoring.Agent.Setup.exe` — мастер первичной настройки.

Если в публикуемой конфигурации нет заранее выданного токена, установщик создаёт
службу, но не запускает её до активации. Администратор школы получает на сервере
одноразовый код, запускает от имени администратора
`C:\Program Files\VkoInternetMonitoringAgent\VkoMonitoring.Agent.Setup.exe` и
указывает сервер, код, название компьютера, кабинет и тип подключения. Мастер
получает привязанные к школе и линии идентификаторы, защищает токен через DPAPI,
включает автоматический запуск и запускает службу. HTTP разрешён только для
локальной разработки; рабочий сервер должен использовать HTTPS.

Для пользователя собран единый русскоязычный EXE-установщик. Он устанавливает или
обновляет службу, сохраняет существующую конфигурацию и предлагает запустить
графическую активацию на новом компьютере:

```text
artifacts\installer\VkoInternetMonitoringAgent-Setup-1.5.0-win-x64.exe
```

Повторная сборка установщика:

```powershell
.\scripts\publish-agent.ps1
.\scripts\build-installer.ps1
```

Процесс подписи с timestamp автоматизирован, но доверенный сертификат ещё нужен. Приёмочная проверка на чистой Windows-машине ещё
обязательны перед промышленным распространением.

Для обновления уже установленной службы с сохранением конфигурации:

```powershell
.\scripts\update-agent.ps1
```

Скрипт `protect-agent-token.ps1` предназначен для однократного перевода ранее установленной версии с открытого токена на DPAPI.

## PostgreSQL

Для локального запуска базы используется `docker-compose.yml`:

```powershell
docker compose -p vko-monitoring up -d postgres
```

После запуска базы включите PostgreSQL-хранилище через переменные окружения:

```powershell
$env:MonitoringApi__StorageProvider = "PostgreSql"
$env:ConnectionStrings__MonitoringDatabase = "Host=localhost;Port=55432;Database=vko_monitoring;Username=vko_monitoring;Password=vko_dev_password"
dotnet run --project .\src\VkoMonitoring.Api --launch-profile http
```

При старте API идемпотентно создаёт/дополняет таблицы школ, линий, устройств, кодов, измерений, инцидентов, пользователей, сессий и аудита, а также индексы истории. Настройки базовых порогов из ТЗ сохраняются вместе с каждым измерением. Пароль в `docker-compose.yml` предназначен только для локальной разработки.

Описание реализованных методов находится в `docs/API.md`, структура базы — в `docs/DATABASE.md`, актуальное состояние требований — в `docs/PROJECT_CHECKLIST.md`, а реестр данных и обязательные меры защиты — в `docs/SECURITY_AND_PRIVACY.md`.

Для диагностики API доступны `GET /health/live` (процесс отвечает) и `GET /health/ready` (API готово к работе и PostgreSQL доступна). Совместимый адрес `GET /health` выполняет полную readiness-проверку.

## Бесплатный демонстрационный сервер Render

В корне репозитория находится `render.yaml`, который создаёт публичный Docker API
и закрытую PostgreSQL на бесплатных тарифах Render. Облачная строка подключения
передаётся через секретную переменную окружения и автоматически преобразуется в
формат Npgsql; пароли и админ-токен в Git не сохраняются.

Пошаговая инструкция и ограничения бесплатного стенда описаны в
`docs/RENDER_DEPLOYMENT.md`.

## Временный публичный сервер через Cloudflare Tunnel

На этапе активной разработки локальный API можно безопасно опубликовать через
временный HTTPS-туннель без открытия портов роутера:

```powershell
.\scripts\start-public-demo.ps1
```

API и PostgreSQL при этом остаются на ноутбуке, а полученный адрес
`https://...trycloudflare.com` доступен школьным компьютерам через интернет.
Подробная инструкция и ограничения находятся в `docs/CLOUDFLARE_TUNNEL.md`.

## Windows-совместимость

Целевая платформа — поддерживаемые редакции Windows 10/11 x64. Скрипт публикации создаёт self-contained пакет `win-x64`, поэтому устанавливать .NET Runtime на школьные компьютеры не требуется. Необходимость отдельного `win-x86` пакета определяется после инвентаризации 32-битных компьютеров.

Веб-панель обслуживается самим API из `wwwroot`. Разделы и ограничения описаны в [WEB_PANEL.md](docs/WEB_PANEL.md); текущий интерфейс инцидентов — в [WEB_INCIDENTS.md](docs/WEB_INCIDENTS.md).

Для веб-моделей также запускайте `node --test tests/web/*.test.mjs`. Воспроизводимые API-проверки и тестовые аккаунты описаны в [USER_ACCESS_TESTING.md](docs/USER_ACCESS_TESTING.md). Не используйте тестовые пароли в рабочем окружении.
