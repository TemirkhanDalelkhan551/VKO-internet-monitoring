# Структура базы данных

PostgreSQL — основное хранилище. JSON — ограниченный локальный режим; справочники, пользователи, активация и инциденты требуют PostgreSQL. Состояние: [PROJECT_SNAPSHOT.md](PROJECT_SNAPSHOT.md).

При старте исполняются встроенные идемпотентные `001_initial_schema.sql`, `002_users_and_audit.sql` и `003_web_operations.sql`. Это не система обратимых миграций: откат приложения не откатывает схему. Перед обновлением нужна резервная копия.

| Таблица | Назначение |
| --- | --- |
| schools | Школа, район/город, адрес, необязательные ФИО/должность/телефон/email, координаты |
| internet_lines | Школа, поставщик, подключение, договорные скорости, номер/дата договора, Primary/Backup/Disabled |
| devices | Школа/линия, идентификатор/имя компьютера, кабинет, связь/версия, хэш токена, блокировка, состояние жизненного цикла, замена и причина списания |
| device_activation_codes | Хэш кода, школа/линия, срок, использование и устройство |
| device_lifecycle_history | Неизменяемая история перепривязки, замены и списания с прежней/новой привязкой, причиной и серверным автором |
| measurements | EventId, время, метрики, состояние/ошибка, длительность, подключение, сервер, внешний IP, версия и снимок порогов |
| incidents | Номер, школа/линия, источник, проблема, статус, жизненные даты, ответственный и последнее событие |
| incident_history | Создание, статусы, назначение, комментарии, восстановление, время и серверный автор |
| monitoring_users | Логин, имя, хэш пароля, роль/область, блокировка и защита входа |
| user_sessions | Хэш токена, пользователь, срок и отзыв |
| audit_events | Попытка запроса до изменения, автор, метод/путь, IP и результат без паролей/токенов/кодов |

## Гарантии

- Координаты nullable только парой: latitude −90…90, longitude −180…180. Отсутствие не заменяется нулём. ADD COLUMN IF NOT EXISTS и проверка наличия CHECK позволяют повторный старт.
- Редактирование сохраняет идентификаторы, устройства, координаты и историю. Пустые необязательные поля очищаются; координаты изменяются отдельным API.
- Токены/коды — SHA-256-хэши. Транзакционная блокировка кода исключает двойную активацию.
- Использованный код можно восстановительно применить в течение 24 часов только с тем же устойчивым идентификатором компьютера и только для активного устройства. Device ID сохраняется, прежний токен отзывается, новый возвращается один раз.
- Замена и списание атомарно переводят устройство из `Active`, блокируют его и удаляют хэш токена. Измерения сохраняются; каждое действие требует причины и записывается в `device_lifecycle_history`.
- measurements.event_id — первичный ключ; повторная доставка не создаёт вторую запись. Пропуски отличаются от нулей. Снимок порогов сохраняет исторические условия оценки; индексы поддерживают историю устройства/школы/линии.
- Частичный уникальный индекс запрещает два активных инцидента линии; Resolved/Closed исключены из него. Возврат восстановленного в работу может получить 409 при наличии другого активного.
- API проверяет токен и DeviceId/SchoolId/LineId; связи закреплены внешними ключами. Область линий применяется до LIMIT и агрегации.
- Роль/привязка/пароль/блокировка отзывают сессии. Actor определяет сервер. Отказ начала аудита блокирует изменение.

Локальная резервная копия автоматизирована скриптом `scripts/backup-postgres.ps1`: custom format проверяется, имеет SHA-256 и ограниченный срок хранения. `scripts/verify-postgres-restore.ps1` восстанавливает её в одноразовую отдельную базу и сверяет основные таблицы. Команды приведены в [OPERATIONS.md](OPERATIONS.md). Расписание, внешнее зашифрованное хранилище и архивирование измерений в самой БД ещё не автоматизированы. Обращения/уведомления — будущие расширения. Тестовые vko_verify_*/vko_web_* отделены от vko_monitoring и не переносятся на Render.
