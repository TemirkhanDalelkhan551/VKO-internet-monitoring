# Структура базы данных

PostgreSQL является основным хранилищем серверной части. JSON-репозиторий используется только для локальной разработки без внешней базы.

## Schools

Хранит организацию образования, район или город, адрес и контактные данные ответственного лица.

## Internet lines

Связывается со школой и описывает отдельную линию Интернета: поставщика, тип подключения, договорные скорости и статус `Primary`, `Backup` или `Disabled`.

## Devices

Связывается со школой и конкретной линией. Хранит идентификатор точки мониторинга, название компьютера, кабинет, тип подключения, время регистрации, последнее подключение, версию агента, SHA-256-хэш токена и признак блокировки. Исходный токен возвращается только при регистрации и в базе не сохраняется.

## Device activation codes

Хранит SHA-256-хэш одноразового кода, привязку к школе и линии, срок действия, время использования и устройство, которое применило код. Открытый код в базе не сохраняется. Транзакционная блокировка записи гарантирует, что один код не сможет одновременно активировать два устройства.

## Measurements

Хранит фактические Download, Upload, Ping, Jitter, Packet Loss, длительность теста, тип активного сетевого подключения, сервер измерения, определённый API внешний IP, состояние соединения, диагностическую причину и версию агента. `event_id` является первичным ключом и обеспечивает идемпотентность.

В каждой записи сохраняется снимок порогов, применённых на момент оценки: Download, Upload, Ping, Jitter и Packet Loss. Изменение настроек в будущем не изменяет исторические условия оценки.

История индексируется по устройству, школе и линии вместе со временем измерения.

## Защита связей

API проверяет одновременно Device ID, School ID, Line ID и токен. Это не позволяет зарегистрированному устройству отправить измерение от имени другой школы или линии. PostgreSQL дополнительно закрепляет связи внешними ключами.

Следующие расширения схемы: пользователи и роли, инциденты, обращения поставщикам, аудит и уведомления.
