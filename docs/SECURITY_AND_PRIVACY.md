# Безопасность и конфиденциальность

## Данные, собираемые агентом

Агент передаёт только технические данные, необходимые для мониторинга:

- идентификаторы школы, устройства, линии и события;
- дату и время измерения;
- Download, Upload, Ping, Jitter и Packet Loss;
- длительность теста, фактический тип подключения и выбранный сервер измерения;
- внешний IP-адрес, определённый сервером по входящему соединению;
- техническое состояние соединения и безопасное описание ошибки;
- версию агента и время последней связи.

Агент не собирает имя пользователя Windows, содержимое файлов, историю браузера, введённые пользователем данные или посещённые сайты. Внешний IP используется только для диагностики интернет-линии: клиент не может передать или подменить его, значение устанавливает API по адресу входящего соединения. Для промышленной эксплуатации срок хранения IP должен быть включён в общую политику хранения измерений.

## Серверные данные

В базе предусмотрены сведения о школе, интернет-линии, провайдере, кабинете и договорной скорости. Поля ФИО, должности, телефона и электронной почты ответственного лица предусмотрены схемой, но текущий API регистрации их не принимает и не заполняет.

Контактные данные считаются ограниченными административными данными. Перед их использованием необходимо:

- сделать их необязательными;
- ограничить просмотр ролями;
- добавить аудит просмотра и изменения;
- определить срок хранения и процедуру удаления;
- не включать их в технические логи, измерения и экспорт без явного основания.

## Уже реализованные меры

- индивидуальный токен устройства хранится на сервере только в виде SHA-256-хэша;
- на компьютере токен защищён Windows DPAPI и доступом `SYSTEM`/администраторов;
- токен привязан к школе, устройству и линии;
- заблокированное устройство не может отправлять данные;
- ответы диагностики не раскрывают строку подключения или внутренний текст ошибки;
- агент запрещает открытый токен при работе с удалённым HTTP-сервером.
- внешний IP не принимается на доверии от агента и перезаписывается сервером.

## Обязательные меры перед эксплуатацией

- HTTPS с доверенным сертификатом для всего внешнего трафика;
- подключение готового одноразового кода первичной активации к установщику и сохранение выданного токена через DPAPI;
- пользователи, роли и принцип минимальных прав;
- аудит активации, блокировки, ротации токена и изменения справочников;
- маскирование секретов и контактных данных в журналах;
- политика хранения, резервного копирования и удаления данных;
- проверка состава CSV/XLSX/PDF-экспорта перед его включением.
