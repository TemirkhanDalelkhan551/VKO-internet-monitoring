# Общая аналитика и экспорт CSV/XLSX

В обзоре доступны средние/минимальные/максимальные Download/Upload/Ping, число и доля проблемных замеров за период (сегодня/7 дней/30 дней/свои календарные даты). Сводка охватывает все доступные организации; поиск/фильтры таблицы школ её не изменяют. Применённые даты и время обновления указаны рядом.

Раздел «Выгрузить отчёт CSV / XLSX»: все доступные школы либо одна школа, один/несколько компьютеров выбранной школы (без отметок — все доступные), статус Online/Degraded/Offline, подробные измерения либо сводка по школам, выбор столбцов и формата.

API:
- `GET /api/reports/options` — разрешённые столбцы и лимит.
- `GET /api/reports/export?kind=measurements|summary&format=csv|xlsx&from=...&to=...`.
- Необязательные `schoolId`, `deviceIds` (UUID через запятую, не более 200; требуется школа), `status`, `fields` (ключи из options, через запятую).
- Bearer-сессия обязательна в рабочем режиме. Те же серверные роли/области доступа; чужой компьютер/школа возвращает 404. Выбранные устройства проверяются по доступным устройствам школы. SQL-предикат линий применяется до LIMIT и группировки.
- Границы периода: from включительно, to исключительно. Без обеих дат — 7 дней; без from — 7 дней до переданного to. UI передаёт UTC-границы локальных календарных дней, включая последний день целиком.
- Даты/время в отчёте — UTC; XLSX содержит типизированные даты/время/числа, лист условий, закреплённую строку и фильтр. CSV — UTF-8 с BOM, разделитель `;`, дробная точка, CRLF. CSV-текст, похожий на формулу, защищён апострофом; XLSX-текст — inlineStr, без формул/внешних ссылок. Числовые нули и отсутствующие показатели различаются.
- По умолчанию выгружены все обязательные поля ТЗ; пользователь может выбрать подмножество. Сводка учитывает те же фильтры, что подробный отчёт. В PostgreSQL проблемность вычисляется по снимку порогов конкретного замера; JSON-режим разработки использует текущую конфигурацию.
- Лимит 20 000 исходных замеров: 422 с требованием сузить выбор, без обрезанного файла. Пустая выборка — корректный файл с заголовками, без вымышленных нулевых строк. `X-Report-Measurement-Count`/`X-Report-Row-Count` показывают точный объём.
- no-store, существующий аудит запросов и admin-read rate limit; токены/внешние IP не являются разрешёнными столбцами.

Контрольная точка этапа экспорта: 177 тестов .NET, 16 тестов веб-моделей, 50 интеграционных проверок отчётов на отдельной PostgreSQL-базе, 2 сценария превышения лимита, независимое сравнение CSV/XLSX для шести областей доступа (пять ролей плюс пустой район), браузерные проверки выгрузки/фильтров/валидации/очистки/отзыва доступа и мобильной формы. XLSX визуально проверен через импорт и рендер Artifact Tool; типы ячеек и строки дополнительно сверены независимым читателем. Проверена Linux Docker-сборка.

Воспроизведение в PowerShell (нужен локальный dev-контейнер `vko-monitoring-postgres-1`, localhost:55432):
```powershell
dotnet publish src/VkoMonitoring.Api/VkoMonitoring.Api.csproj -c Release -o artifacts/api-test
./scripts/start-web-test-fixtures.ps1 -PublishDirectory artifacts/api-test -Port 5090
./scripts/verify-report-integration.ps1 -BaseUrl http://localhost:5090
```
Fixture создаёт отдельную БД `vko_web_*`, тестовые школы/линии/замеры и учётные записи web-admin/web-school/web-district/web-regional/web-provider/web-empty с тестовым паролем web-test-only-2026. После подготовки общий админ-токен отключается. PID и лог находятся в artifacts/web-fixtures; после тестирования остановить именно этот экземпляр по сохранённому PID. Основной API и рабочая БД не изменяются. Повторный запуск требует свободного порта. При повторных входах соблюдайте лимит 10 попыток/минуту на IP.

Минимальная XLSX-структура соответствует [SpreadsheetML](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document); серверный writer использует стандартные ZipArchive/XmlWriter и не требует Excel или стороннего сервиса.

На Render опубликованы карта, справочники, коды, инциденты, сводки районов/поставщиков, пользователи, аудит и прозрачный рейтинг школ/линий. AI-черновик обращения формируется по фактическим данным инцидента и агрегированным замерам, остаётся редактируемым, подтверждается человеком и не отправляется автоматически. Печать/сохранение в PDF выполняется средствами браузера; утверждённого серверного PDF-шаблона пока нет. Актуальные проверки — в PROJECT_SNAPSHOT.md.
