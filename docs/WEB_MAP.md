# Карта школ ВКО

Карта находится в общем обзоре под таблицей школ. Leaflet 1.9.4 включён в проект локально; подложка OpenStreetMap загружается по HTTPS. Источник подложки, атрибуция и исходный центр задаются в `src/VkoMonitoring.Api/wwwroot/map-config.json`. При изменении источника перезапустите API: разрешённый CSP-origin изображений вычисляется из этой конфигурации. Внешние скрипты и inline-стили остаются запрещены.

На карте отображаются только школы из авторизованного `/api/schools` с заполненными координатами. Фильтры района, статуса основной линии, поставщика, типа подключения и поиска общие для карты и таблицы. Поставщик и тип подключения должны совпасть на одной доступной пользователю линии. При фильтрации по резервной линии цвет точки по-прежнему относится к доступной основной линии; резервная её не подменяет.

Пять цветов отражают Normal, Unstable, Critical, NoConnection и Unknown. Подсказка при наведении показывает название, при нажатии открывается таблица пяти метрик, свежести, времени замера и связи с агентом; кнопка открывает существующую карточку школы. Данные выводятся как текст, а не пользовательский HTML. Маркеры доступны с клавиатуры. Отсутствие heartbeat не меняет качество последнего актуального замера.

Школы без координат остаются в таблице и перечисляются отдельно под картой с переходом в карточку. Координаты не выводятся из IP или районного центра, автоматического геокодирования нет. При недоступности подложки точки и таблица доступны с сообщением об ошибке.

## Заполнение координат

Администратор и областной оператор могут раскрыть «Указать или изменить координаты школы», выбрать школу, ввести широту и долготу и сохранить. Поддерживаются десятичные точка и запятая. Обе координаты обязательны вместе; допустимы широта [-90,90] и долгота [-180,180]. Очистка обоих полей удаляет точку. Нули являются координатами, а не отсутствующими значениями. Перед вводом нужно проверить точное положение реальной школы.

API: `PUT /api/schools/{schoolId}/location`, тело `{"latitude":49.97,"longitude":82.61}` либо `{"latitude":null,"longitude":null}`. Требуются PostgreSQL и административная/областная сессия. Операция проходит существующий аудит и admin-write rate limit. Чужая/несуществующая школа не раскрывается. JSON-режим разработки возвращает 501 для изменения координат.

В PostgreSQL добавлены nullable double precision `schools.latitude` и `schools.longitude`, парный CHECK с ограничением диапазона. Схема расширяется при старте API идемпотентно; существующие школы получают NULL. Оба поля возвращаются в списке и карточке школы и сохраняются при агрегации линий.

## Проверка

```powershell
dotnet publish src/VkoMonitoring.Api/VkoMonitoring.Api.csproj -c Release -o artifacts/api-map-test
./scripts/start-web-test-fixtures.ps1 -PublishDirectory artifacts/api-map-test -Port 5094
./scripts/verify-map-integration.ps1 -BaseUrl http://localhost:5094
dotnet test VkoInternetMonitoring.sln -c Release
dotnet build VkoInternetMonitoring.sln -c Release
node --test tests/web/*.test.mjs
```

Fixture использует отдельную тестовую БД. Координата тестовой школы синтетическая, не подтверждает положение реальной организации. Интеграционный сценарий проверяет все пять ролей, пустую область, отсутствие чужих линий/основных метрик для резервного поставщика, сохранение/удаление координат, диапазоны и аудит. Локальные тестовые учётные записи не предназначены для Render.

Карта впервые опубликована в `e130918` и остаётся доступна в текущем Render-деплое `f33c626`; подтверждены `Live` и `Healthy`. Рабочие координаты реальных школ нужно заполнить отдельно. Работа второго компьютера принята пользователем. Актуальный снимок: PROJECT_SNAPSHOT.md.
