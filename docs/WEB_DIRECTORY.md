# Школы, линии, контакты и договоры

В обзоре веб-панели Administrator и Regional могут раскрыть «Школы, линии, контакты и договоры». Изменения записываются в PostgreSQL и аудит API. Остальные роли читают данные в своей области доступа.

1. Выберите «Новая школа», заполните название, район, адрес и при необходимости контакты ответственного. Нажмите «Сохранить школу».
2. Для сохранённой школы выберите «Новая линия», заполните название, поставщика, тип подключения, назначение линии и при необходимости договорные скорости, номер и дату договора. Нажмите «Сохранить линию».
3. Для изменения выберите существующую школу или линию. Кнопки загрузки сохранённых данных отменяют изменения формы. Пустые необязательные поля очищают сохранённое значение.
4. Контакты видны в карточке школы, договор — рядом с показателями линии. При свежем замере ниже договорной скорости появляется указание показателя; нормативный статус качества рассчитывается прежними правилами.

Название обязательно, email проверяется, договорная скорость должна быть положительной с точностью до трёх десятичных знаков. Поддерживаются точка и запятая. Создание справочников не создаёт устройства, токен или измерение. Редактирование сохраняет идентификаторы, координаты школы, устройства и историю. Смена района или поставщика меняет область доступа соответствующих пользователей.

Подключение компьютера: выберите сохранённые школу и линию, затем в блоке «Подключить компьютер» выдайте одноразовый код, установите EXE и активируйте агент. Подробнее — `WEB_ACTIVATION.md`. Физическое удаление не предусмотрено; линию можно отключить. Расписания замеров, пороги, реестр поставщиков и прикрепление файлов договора остаются отдельными задачами. Форма сохраняет реквизиты договора.

API: POST `/api/schools`, PUT `/api/schools/{schoolId}`, POST `/api/schools/{schoolId}/lines`, PUT `/api/schools/{schoolId}/lines/{lineId}`. Создание возвращает 201 и идентификатор, редактирование — 204, неверные поля — 400, отсутствие объекта — 404, отсутствие доступа — 401/403. Для справочников требуется PostgreSQL; файловый режим возвращает 501. Поля запросов перечислены в `Models/DirectoryRequests.cs`.

Проверка локально: `dotnet test`, `dotnet build -c Release`, `node --test tests/web/*.test.mjs`. После публикации API в `artifacts/api-directory-test` запустите `scripts/start-web-test-fixtures.ps1 -PublishDirectory artifacts/api-directory-test -Port 5095`, затем `scripts/verify-directory-integration.ps1`. Скрипт работает только с loopback; использовать исключительно отдельную тестовую базу, создаваемую fixture-скриптом. Созданные тестовые справочники остаются в этой базе.
