# Архитектура VKO Internet Monitoring

Этот документ описывает структуру, подтверждаемую текущими проектами решения, конфигурацией запуска и регистрацией зависимостей. Детальные HTTP-контракты находятся в [API.md](../API.md), структура хранения — в [DATABASE.md](../DATABASE.md).

## Назначение и границы

Система измеряет качество интернет-соединения на Windows-компьютерах школ, надёжно доставляет результаты на сервер и предоставляет защищённую веб-панель для наблюдения, аналитики и административных операций.

В репозитории находятся:

- Windows-служба измерений и локальная очередь;
- WinForms-мастер установки, активации и локального состояния;
- ASP.NET Core API;
- статическая веб-панель, обслуживаемая API;
- PostgreSQL-схема и ограниченный файловый режим для локальной разработки;
- автоматические и интеграционные проверки, а также PowerShell-скрипты эксплуатации.

## Компоненты

| Компонент | Путь | Ответственность |
| --- | --- | --- |
| Agent Core | `src/VkoMonitoring.Agent.Core` | Доменные типы, конфигурация, интерфейсы и оркестрация измерений, расписания, нагрузки, очереди и повторов. Не зависит от HTTP, файловой системы, Windows-службы или базы данных. |
| Agent Infrastructure | `src/VkoMonitoring.Agent.Infrastructure` | ICMP/HTTP-измерения, сетевой и аппаратный контекст Windows, HTTP-клиенты API, DPAPI и JSON-файлы очереди. |
| Agent Host | `src/VkoMonitoring.Agent` | Composition root и фоновые worker-процессы измерений, доставки очереди, heartbeat и инвентаризации. Запускается как Windows-служба или консольный процесс. |
| Agent Setup | `src/VkoMonitoring.Agent.Setup` | WinForms-активация, проверка prerequisites, запись локальной конфигурации, управление службой и просмотр состояния текущего устройства. |
| Monitoring API | `src/VkoMonitoring.Api` | Minimal API, аутентификация и области ролей, валидация, хранение, инциденты, отчёты, рейтинг, health checks и внешние уведомления. |
| Web UI | `src/VkoMonitoring.Api/wwwroot` | Одностраничная панель без отдельной npm-сборки; использует пользовательскую Bearer-сессию и API того же origin. |
| Tests | `tests/VkoMonitoring.Agent.Tests`, `tests/web` | xUnit-тесты домена, инфраструктуры, API и setup; Node.js-тесты чистых моделей веб-интерфейса. |

Зависимости проектов направлены от host/infrastructure к Core. API использует доменные типы Core, но не зависит от Windows host или setup.

## Контекст выполнения

```text
Windows-компьютер школы
  Setup.exe -> локальная конфигурация + DPAPI token
  Windows Service -> измерения + heartbeat + инвентаризация
          |
          | HTTPS, X-Device-Token
          v
ASP.NET Core API + статическая Web UI
          |
          +-> PostgreSQL (рабочий режим)
          +-> JSON-файлы (ограниченный локальный режим)
          +-> AI provider (необязательный черновик обращения)
          +-> Telegram Bot API (необязательные уведомления)
```

API и веб-панель развёртываются одним приложением. `render.yaml` описывает Docker Web Service и PostgreSQL 17; `docker-compose.yml` поднимает PostgreSQL 17 для локальной разработки. Автоматический деплой Render отключён конфигурацией.

## Хранение

`MonitoringApi:StorageProvider` выбирает реализацию репозиториев:

- `PostgreSql` — рабочий контур для пользователей, активации, справочников, инцидентов, аудита и административных операций;
- `Json` — локальный режим для приёма измерений и быстрой разработки без внешней базы. Неподдерживаемые в этом режиме операции возвращаются через специальные `Unsupported*Repository`.

При старте PostgreSQL-режима `PostgresDatabaseInitializer` идемпотентно применяет встроенные SQL-ресурсы `001`–`004`.

## Основные архитектурные свойства

- Измерение сначала сохраняется в локальную файловую очередь, а затем удаляется только после успешной доставки.
- Повторная доставка безопасна: `EventId` является первичным ключом серверного измерения.
- Heartbeat не запускает измерение и отдельно отражает связь агента с сервером.
- Устройство аутентифицируется собственной привязкой School ID, Device ID, Line ID и токеном.
- Пользовательские операции проходят через серверную Bearer-сессию, проверку роли и области данных.
- Веб-панель не является границей авторизации: доступ повторно проверяется API.
- Внешние AI- и Telegram-интеграции необязательны и не входят в критический путь приёма измерений.
