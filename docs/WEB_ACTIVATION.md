# Выдача кода активации в веб-панели

Актуальная версия опубликована на Render из текущего `main`. Актуальные границы версии и проверки: [PROJECT_SNAPSHOT.md](PROJECT_SNAPSHOT.md).

Двухшаговый мастер EXE 1.4.0 добавляет управляемое восстановление активации. После активации локальная панель позволяет запросить полный тестовый замер сразу, не дожидаясь расписания.

Функция доступна Administrator и Regional в разделе «Школы, линии, контакты и договоры».

1. Выберите сохранённую школу и её сохранённую линию. Если их ещё нет, сначала создайте и сохраните их в формах выше.
2. В блоке «Подключить компьютер» задайте срок кода: от 5 до 1440 целых минут, по умолчанию 30.
3. Нажмите «Выдать код активации». Панель покажет код, выбранную школу/линию и время истечения в часовом поясе компьютера.
4. Скопируйте код кнопкой или вручную. На другом компьютере запустите EXE-установщик агента и введите код; рабочий адрес API уже заполнен.
5. Нажмите «Проверить и продолжить». Мастер проверит Windows, права, службу, место на диске, readiness/TLS сервера, малые Download/Upload-запросы и код без его расходования.
6. Сверьте показанные школу, линию, поставщика и срок кода. Только после этого нажмите «Подтвердить и запустить».
7. Дождитесь результата запуска: мастер до 15 секунд проверяет первый heartbeat. Если связь ещё не появилась, служба остаётся запущенной, а состояние можно повторно проверить через минуту.

Один код подключает один компьютер. Если сервер уже зарегистрировал устройство, а локальная запись конфигурации прервалась, тот же мастер и тот же код можно повторить на том же компьютере в течение 24 часов. Сервер сверяет устойчивый идентификатор машины, сохраняет Device ID, отзывает прежний токен и один раз выдаёт новый. Другой компьютер получит отказ. Для обычного второго компьютера нужен отдельный код. Код локальной тестовой базы нельзя использовать с API Render: выдача и активация должны обращаться к одному серверу и одной базе.

Используется существующий POST `/api/activation-codes` с персональной Bearer-сессией. Сервер хранит хэш, проверяет срок и однократность атомарно, выдача записывается в аудит. Код не сохраняется в localStorage/sessionStorage, URL или логах веб-панели. Ответ API имеет Cache-Control: no-store. Изменение школы/линии, выход из системы и истечение срока очищают показанный код. Поздний ответ прежней сессии не отображается.

Мастер использует `POST /api/devices/activation-preview`: запрос принимает код и идентификатор компьютера в теле, находит код только по SHA-256-хэшу и возвращает привязку для подтверждения. Для использованного кода preview доступен только тому же компьютеру в 24-часовом окне. Фактическая регистрация или восстановительная выдача нового токена выполняются атомарно через `POST /api/devices/activate`.

«Скрыть код» очищает открытое значение с экрана, но не отзывает код на сервере. Повторно прочитать скрытый секрет нельзя; действующий неиспользованный код можно отдельно отозвать в реестре. Реестр показывает статус, школу, линию, автора и время без открытого значения кода.

Локальная проверка: опубликуйте API в `artifacts/api-activation-test`, запустите `scripts/start-web-test-fixtures.ps1 -PublishDirectory artifacts/api-activation-test -Port 5097`, затем `scripts/verify-web-activation.ps1`. Скрипт предназначен исключительно для изолированной тестовой базы на loopback и создаёт тестовое устройство. Не запускайте против рабочей базы. Повторные тестовые входы могут упереться в ограничение 10 входов в минуту; дождитесь восстановления лимита.


## Реестр и отзыв

Administrator и Regional видят последние коды без секретного значения: школа, линия, время выдачи, срок и статус `Действует`, `Использован`, `Истёк` или `Отозван`. Действующий неиспользованный код можно отозвать; после отзыва preview и активация возвращают отказ. Выданное значение кода по-прежнему показывается только один раз.
