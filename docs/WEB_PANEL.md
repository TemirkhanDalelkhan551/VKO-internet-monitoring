# Первый этап веб-панели

Интерфейс обслуживается самим API из `wwwroot`, без отдельного сервера и npm-зависимостей. Открывайте корневой адрес API; `/health/ready` остаётся проверкой готовности сервера.

Вход использует `/api/auth/login`, пользователь — `/api/auth/me`, данные — `/api/schools`. Токен находится только в памяти страницы: обновление страницы требует нового входа. Выход отзывает сессию; ответ 401 очищает данные и возвращает форму входа. Пароли, токены и данные пользователя не сохраняются в localStorage.

Обзор показывает только разрешённые сервером школы и линии. Поставщик видит свои линии. Основная линия определяет сводку школы; резервные линии раскрываются отдельно. Качество интернета, свежесть замера и присутствие агента — независимые показатели. Старый нормальный замер не означает нормальное соединение сейчас.

Доступны поиск школы/района/поставщика, фильтр района и статуса, ручное обновление и обновление раз в минуту при видимой странице. На телефоне широкая таблица прокручивается горизонтально.

Следующие этапы: отдельная карточка школы, список устройств, история и графики, инциденты, управление пользователями и просмотр аудита. Карта, редактирование настроек и экспорт ещё не реализованы.

Проверка: `dotnet test VkoInternetMonitoring.sln`, `dotnet build VkoInternetMonitoring.sln`, `node --test tests/web/dashboard-model.test.mjs`, интеграционный сценарий `scripts/verify-api-integration.ps1`. Браузерные проверки выполнялись на отдельной PostgreSQL-базе: все пять ролей, пустая область доступа, фильтры, разные линии, выход, перезагрузка и истечение сессии.
