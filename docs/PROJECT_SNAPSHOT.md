docker build -f src/VkoMonitoring.Api/Dockerfile -t vko-api:snapshot .

Веб-сценарии: опубликовать API в отдельный artifacts/api-test, запустить start-web-test-fixtures.ps1 с этим каталогом и свободным портом, затем нужный verify-скрипт с тем же BaseUrl. Для каждой проверки использовать свежую fixture; остановить именно её PID после проверки. БД должны быть local vko_web_*/vko_verify_*, не рабочая vko_monitoring и не Render. Тестовые пароли: USER_ACCESS_TESTING.md. Приватные логи/базы/резервные копии и EXE остаются вне Git.

## Границы готовности

Не завершены: AI-черновик отложен по решению пользователя; единый пошаговый мастер подключения; отдельный серверный PDF по утверждённому шаблону; внешнее зашифрованное хранение резервных копий; централизованные логи; автоматические обновления; фактическая подпись EXE доверенным сертификатом; шифрование очереди; нагрузка/24–72 часа/калибровка; физическая проверка нескольких линий и дополнительные версии Windows. Read-only сценарий пяти ролей готов и прошёл локально, но рабочий Render ещё требует учётные данные пяти ролей.

Бесплатная PostgreSQL Render по исходному развёртыванию истекает 18.10.2026; эту дату нужно перепроверить в панели перед эксплуатацией. Сервер может засыпать, первый запрос задерживаться. Утверждение «система полностью готова» этим снимком не делается. Дальнейшие приоритеты — PROJECT_CHECKLIST.md; показ — DEMO_CHECKLIST.md.
