# Снимок проекта — 24 сентября 2026

Контрольная точка исходников, документации и воспроизводимых проверок. Приложение вручную опубликовано на Render из коммита `ae19197` и имеет статус `Live`; readiness API и PostgreSQL подтверждены как `Healthy`. GitHub `main` содержит этот коммит и последующее обновление документации. Версия агента/установщика — 1.5.0.

Все они прошли на изолированных локальных базах; отдельно прошли 230 .NET- и 32 JS-теста. API-сценарий проверяет восстановление активации, отказ чужой машине, жизненный цикл и отзыв токена, пять ролей, область рейтинга, отображение открытых инцидентов в сводке школы и их снятие после восстановления. Интерфейс явно разделяет качество и свежесть замера, heartbeat агента и открытые инциденты; недоступность API показывает как проблему сервера с отметкой последнего успешного обновления. Реальный браузерный прогон подтвердил и отображение открытого инцидента, и отдельное предупреждение при остановке тестового API.

```powershell
dotnet test VkoInternetMonitoring.sln -c Release
dotnet build VkoInternetMonitoring.sln -c Release
node --test tests/web/*.test.mjs
docker build -f src/VkoMonitoring.Api/Dockerfile -t vko-api:snapshot .
pwsh -NoProfile -File scripts/verify-api-integration.ps1 -ApiPort 5084
```

Веб-сценарии: опубликовать API в отдельный artifacts/api-test, запустить start-web-test-fixtures.ps1 с этим каталогом и свободным портом, затем нужный verify-скрипт с тем же BaseUrl. Для каждой проверки использовать свежую fixture; остановить именно её PID после проверки. БД должны быть local vko_web_*/vko_verify_*, не рабочая vko_monitoring и не Render. Тестовые пароли: USER_ACCESS_TESTING.md. Приватные логи/базы/резервные копии и EXE остаются вне Git.

Бесплатная PostgreSQL Render по исходному развёртыванию истекает 18.10.2026; эту дату нужно перепроверить в панели перед эксплуатацией. Сервер может засыпать, первый запрос задерживаться.
