# Проверка пользователей, ролей и аудита

Автоматические проверки:

```powershell
dotnet test .\VkoInternetMonitoring.sln --configuration Release
dotnet build .\VkoInternetMonitoring.sln --configuration Release
```

Полная интеграционная проверка API в отдельной PostgreSQL-базе:

```powershell
docker compose -p vko-monitoring up -d postgres
pwsh -File .\scripts\verify-api-integration.ps1 -ApiPort 5084
```

Сценарий предназначен для Windows/PowerShell 7 и стандартного локального PostgreSQL проекта (порт 55432, контейнер `vko-monitoring-postgres-1`). Он сам собирает API в `artifacts/integration-build`, создаёт базу с уникальным префиксом `vko_verify_`, случайные тестовые токены и учётные записи. База рабочего проекта `vko_monitoring` и установленная служба агента не изменяются. Занятый порт не освобождается автоматически. При провале любой проверки сценарий завершается с ошибкой.

Результаты и журналы находятся в `data/integration-tests`. Тестовая база сохраняется для расследования. Тестовые пароли/токены не выводятся и не сохраняются в отчётах. Сценарий запускается в отдельном процессе `pwsh`, чтобы его переменные среды не меняли среду рабочего API.

На 18.09.2026 проходят 161 автоматический тест и 138 интеграционных проверок:

- прежние сценарии регистрации, активации, токенов, замеров, идемпотентности и инцидентов;
- разделение основной/резервной линии, свежести и качества замера;
- все пять ролей, школа/район/поставщик/пустая область доступа;
- отсутствие чужих линий в карточке, устройствах, последних замерах и SQL-аналитике;
- запрет административных операций, в том числе при другом регистре URL;
- подмена автора, блокировка/разблокировка, отзыв по роли/паролю, выход и истечение сессии;
- защита последнего активного администратора, ограничение входа и временная блокировка;
- наличие аудита без паролей/токенов и отказ изменения данных при недоступности журнала.

Рабочий API обновлён после резервной копии базы. Проверен через HTTPS Tunnel; установленный агент подтвердил heartbeat после обновления. Первичный администратор создан, совместимость с общим `X-Admin-Token` выключена. Веб-форма входа и пользовательская приёмка веб-панели остаются следующим этапом.

Используется штатный [PasswordHasher ASP.NET Core Identity](https://learn.microsoft.com/en-us/dotnet/api/microsoft.aspnetcore.identity.passwordhasher-1?view=aspnetcore-10.0).
